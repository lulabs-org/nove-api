# 参会者总结拆表维护窗口

此变更由两条迁移组成：`20260814010000_add_user_tracking_reports` 负责扩展和幂等回填，`20260814020000_split_participant_summaries` 负责最终收缩。第二条迁移禁止在总结任务仍写入时执行。

## 上线前

1. 先部署并应用此前所有迁移，包括 `20260813040000_add_channel_management`。
2. 执行数据库备份，并记录备份文件和恢复命令。
3. 暂停 API 写入、腾讯会议回调消费者、BullMQ 周期任务与手动生成入口。
4. 确认相关队列已排空，数据库中 `participant_summaries` 的总数连续两次采样不再变化。
5. 运行 `pnpm audit:participant-summary-split`；任一异常计数非零时不得执行收缩迁移。

## 切换

1. 执行 `pnpm backfill:user-tracking-reports` 完成停写后的最终幂等追平。
2. 执行 `pnpm db:migrate:prod`。收缩迁移会在缺失身份、回填不完整或同级关系存在时主动失败。
3. 再次运行审计脚本，确认录制总结和长期报告的每个版本组只有一个有效最新版本。
4. 同步发布调用新路径的客户端，完成录制总结 CRUD、生成接口和长期追踪 CRUD 冒烟测试。
5. 确认不存在旧 DTO 队列任务后恢复消费者和定时任务。

## 回滚

收缩迁移执行后不要尝试用逆向 SQL 恢复旧结构。冒烟失败时保持任务暂停，回滚应用并从维护窗口备份恢复数据库。
