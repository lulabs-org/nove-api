# 项目愿景与目标 (Project Goals)

Nove API 的核心定位是一个**以“会议智能管理与分析”为核心的企业级多租户后端平台**。本部分梳理了项目的核心愿景、技术架构目标以及近期的阶段性开发里程碑，以帮助开发者和贡献者更好地理解项目价值和演进方向。

## 🎯 1. 产品与业务目标 (Product Vision)

### 1.1 智能化会议沉淀
* **自动化资产捕获**：通过深度集成**腾讯会议**（如 Webhooks 与 OpenAPI），实现组织内会议数据的自动拉取、存储和管理。
* **AI 赋能分析**：利用 **OpenAI** 提取会议摘要、关键行动项（Action Items）以及数据洞察，将原始会议记录转化为高价值的企业数字资产。

### 1.2 数据流转与协同
* **业务无缝打通**：将原本孤立在后端的会议数据、统计报表和智能洞察，单向或双向同步至**飞书多维表格 (Bitable)**。
* **数据驱动管理**：使得非技术人员和管理层能够直接在熟悉的协同办公软件中查看、流转并跟进会议产生的结果与任务。

### 1.3 企业级权限管控
* **多租户数据隔离**：作为一个多租户系统，严格保障不同企业或部门之间的数据独立性与安全性。
* **灵活的 RBAC 体系**：提供完善的用户认证（Authentication）与细粒度的组织/角色权限管理（Authorization）。

## 🏗️ 2. 技术与架构目标 (Technical Architecture)

### 2.1 高可用与异步处理
* **异步解耦**：系统大量引入 **Redis** 与 **BullMQ** 处理耗时任务（如：定时拉取长录像、请求大语言模型进行推理分析、批量同步飞书数据等），以确保核心 API 的响应速度。
* **健壮性**：即使在第三方服务（如 OpenAI API 或飞书 API）出现波动或限流时，也能通过队列重试机制保障数据最终一致性。

### 2.2 现代化与类型安全
* **技术栈选择**：采用 `NestJS 11 + TypeScript 5.7 + Prisma + PostgreSQL 17` 这一现代且强类型的技术组合。
* **可维护性**：通过 ESLint、Prettier 进行严格的代码风格约束，结合全面的自动化测试（单元测试、集成测试、E2E 测试），为长期维护保驾护航。

### 2.3 多协议与标准 API 支持
* **API 标准化**：提供规范的 RESTful API，并借助 Swagger 自动生成文档供前端和第三方对接。
* **GraphQL 支持**：提供 GraphQL 支持，以满足不同端（Web 端、移动端、内部数据报表看板等）对数据获取的不同颗粒度需求。

## 🚀 3. 近期开发里程碑 (Current Milestones)

* **底层数据模型加固**：设计和完善 `MeetingUserAction`（用户会议行为）与 `ParticipantSummary`（参会人总结）等模型，以支撑未来更丰富的数据统计分析场景。
* **安全性增强**：全面审视系统对外暴露的端点（如邮件服务及 Webhook 端点），添加并完善 Guards 鉴权，防御潜在的越权访问或滥用风险。
* **MCP 能力集成**：对接 Model Context Protocol (MCP) 服务器，使 LLM 等外部智能体能够直接调用或理解 Nove API 内部业务逻辑，探索更智能的开发与运行范式。
